# UUIDv7 comme identité unique des entités

## Mission

Remplacer le couple `id` (int auto-increment) + `secureId` (colonne string aléatoire)
par un identifiant unique : un **UUIDv7**, généré côté PHP dans le constructeur
d'`AbstractEntity`. Le rôle de « masquage de l'ordre de création » que portait
`secureId` est abandonné — UUIDv7 fuit son horodatage, c'est assumé.

Périmètre validé par l'opérateur : **toute la suite PHP, clé JSON comprise**
(`secureId` → `id` dans le format de réponse). Les apps Symfony consommatrices ne sont
pas dans le périmètre ; leurs migrations viendront après.

## Pourquoi v7, et pourquoi dans le constructeur

v4 est aléatoire, donc fragmente l'index B-tree en clé primaire. v7 préfixe l'uuid d'un
timestamp milliseconde : monotone comme un auto-increment. C'est ce qui permet de garder
`EntityHelper::sortById()` et `AbstractRepository::orderByDefaultPagination()` corrects
sans les toucher.

Génération dans le constructeur plutôt que `#[CustomIdGenerator]` : l'entité porte son
identité **avant tout persist**, sans base — propriété dont la todo « entités sans
Doctrine » (`b4bf06d38add`) a directement besoin. Doctrine hydrate sans passer par le
constructeur, donc aucun conflit à la lecture.

## Les idiomes que ça casse

`Uuid` est un objet :

- `$a->getId() === $b->getId()` compare les instances → toujours faux. Devient `->equals()`.
- `$array[$entity->getId()]` en clé de tableau → cast `(string)` obligatoire.
- `if (! $entity->getId())` comme test « entité neuve » → l'id existe désormais toujours.

Et un quatrième, propre à l'héritage : **toute entité qui définit son propre
constructeur doit appeler `parent::__construct()`**, sinon elle n'a plus d'id. Un seul
cas dans la suite (`symfony-translations/AbstractTranslation`), corrigé — mais c'est le
piège numéro un pour les apps qui migreront.

## Trouvé en chemin

`symfony-forms/FormController::ROUTE_PATH_ENTITY_PROCESSOR_SUBMIT` déclare `{id}`, mais
`EntityEditFormDataResolver` lisait l'attribut `secureId` — qui n'était donc jamais
fourni. Le renommage aligne les deux et corrige ce bug latent au passage.

## Vérification

`php -l` passé sur les 36 fichiers PHP modifiés, dans un conteneur `php:8.3-cli` : aucun
fichier en erreur. **Aucun test n'a pu tourner** : les packages n'ont pas de `vendor/`
installé et la machine n'a pas de `php` hors conteneur. Rien n'a été exécuté contre une
vraie base — la compatibilité `UuidType` ↔ Doctrine reste à éprouver sur une app.
